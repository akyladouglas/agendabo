# Plano — Compartilhamento de agenda entre usuários (par, somente leitura)

- Data: 2026-10-12 | Status: **concluído** (Etapa 8 em fechamento; gates verdes, review duplo resolvido, nada commitado — commits são do humano)
- Spec: `.ia/specs/compartilhamento/compartilhamento-agenda-par.spec.md` (APROVADA, zero abertos, humano 2026-10-12) | Fase do roadmap: etapa adicional pós-Fase 9
- Orquestrador: subagent feature-orchestrator | v1 do plano

## 1. Objetivo

Entregar o vínculo compartilhado dono→convidado (papel fixo `read`, par ordenado, dois sentidos
independentes) com convite por e-mail (token opaco TTL 24h, quota 3/30min, anti-enumeration
total), leitura da agenda emprestada (`GET /appointments?owner=` + web `/agenda` read-only com
seletor de fonte no fuso do convidado), `/perfil` com gestão + auditoria
(`shared_agenda_audit_events` + "Histórico"), e bot/worker com resumo diário por agenda
emprestada, consulta com alvo compartilhado e negação determinística de escrita. Zero escrita
pelo convidado, zero regra nova de data (schedule-core reusado).

## 2. Análise de profundidade

**Vizinhos confirmados (referências de padrão):**

- Quota/token com `now` injetável: `apps/api/src/modules/auth/password-reset.ts`
  (`evaluateResetQuota`, TTL) + orquestração anti-enumeration em
  `auth-password-reset.service.ts` (202 uniforme para QUALQUER entrada, CAS anti-corrida,
  P2002 silenciado, falha do Resend = log interno + resposta idêntica).
- E-mail: `MailService` (`modules/auth/mail.service.ts`, único ponto de Resend — regra do
  depcruise) + HTML table-based em `password-reset-email.ts`/`verification-email.ts`
  (paleta fixa, `escapeHtml` defensivo).
- Token: `randomToken()`/`sha256Hex`/`codeMatches` em `auth.service.ts`; índice parcial único
  SEMPRE via SQL na migração (precedentes: outbox digest, `password_reset_kind`, admin —
  `@@unique` total do Prisma NÃO expressa WHERE parcial).
- `GET /appointments` hoje: `AppointmentsService.list(userId, raw)` com
  `listAppointmentsQuerySchema` (`packages/contracts/src/api/appointments.ts`), interseção
  half-open `startsAt < to AND endsAt >= from`; zod de RESPONSE não existe no server — a web
  dá `safeParse` client-side (`useAppointments.query.ts` + `qk.appointments(from, to)`).
- Auditoria: padrão `BotEventsService` (metadata validada por zod ANTES de gravar, gravação
  best-effort que nunca estoura o chamador) — a F.4 pede a mesma disciplina em tabela própria
  - leitura paginada por vínculo.
- Bot: `SchedulingFlowService.handleText` classifica a intenção off-flow; `consultar` cai em
  `AgendaQueryService.run` (período via `ConsultaInterpreterService`; lista via
  `listOverlapping`; régua 0/1/N, truncar 10, agregado ≥30 em `agenda-query.ts` puro); `criar`
  abre a máquina `SchedulingFlowMachine` — a negação de escrita emprestada precisa acontecer
  ANTES de `openFlow`.
- Worker: `DispatchService.buildDigestText` monta o corpo do digest no dia civil do usuário
  (`userDayRange`/`appointmentsOnUserDay`, offset medido na borda via `offsetProvider`) — ponto
  exato de injeção da seção compartilhada (linha do outbox/idempotência não mudam — ADR-009).
- Web: `useAgendaPage.composable` (offset DO VISUALIZADOR via `measureTzOffset`,
  `groupByLocalDayTouched`/`sliceItemToRange`/`layoutDayTimeline`), `AgendaNav` (seletor de
  visão — o seletor de fonte entra ao lado), `ProfilePage` com `SessionsCard` (a nova seção
  nasce ao lado), router com `requireAuth` + exceção documentada de token-opaco-em-query
  (`/redefinir-senha?token=`).
- Fronteiras: `.dependency-cruiser.cjs` `CROSS_MODULE_EDGES` é o grafo de imports entre
  módulos — o módulo novo `modules/shared-agendas` precisa de entrada própria + arestas
  novas (ver D1).

**Gaps mapeados:**

- `interpretarConsultaSchema`/tool não têm campo de alvo (precisa de `alvo`/`alvo_nome` — F.2).
- Não existe zod de RESPONSE para a listagem — o payload filtrado do convidado precisa de
  schema próprio nos contracts para a web parsear (e para o teste assertar ausência de
  `rawText`/`reviewReason`).
- `qk.appointments(from, to)` não tem dimensão de fonte (D9 da spec C.17 exige chave por fonte).
- `BOT_MESSAGES` não tem as mensagens de compartilhamento (negação de escrita, alvo ambíguo,
  acesso encerrado, saiu do compartilhamento).
