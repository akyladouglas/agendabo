## 1. Objetivo

Sessão de refresh tokens morre em 24h absolutas do login (`SESSION_ABSOLUTE_TTL_HOURS=24`); refresh token vira chave de gestão de dispositivos (listar / derrubar outras); logout revoga no banco (bug atual: só limpa cookie); e-mail de alerta em login de dispositivo novo; web redireciona para /login imediatamente quando a sessão morre.

## 2. Análise de profundidade

- `auth-signup.service.ts`: `login()` cria refresh com `expiresAt = now + REFRESH_TOKEN_TTL_DAYS`; `refresh()` faz `findUnique` por tokenHash `include: { user: true }` e rotaciona delete+create com TTL fixo. Nenhum sabe de `loginAt`/ip/ua.
- `auth.controller.ts`: `logout` é `@Public()` e só faz `clearCookie` (bug). `REFRESH_COOKIE_OPTS` sem maxAge no clearCookie; login/refresh setam maxAge fixo de 30d.
- Prisma `RefreshToken { id, tokenHash unique, expiresAt, createdAt, userId }` — sem loginAt/ip/userAgent.
- Web: `authStore.logout()` dispara logout fire-and-forget e não redireciona; interceptor de `api.ts` chama `refreshOnce` que engole o erro (perde o código `session_expired`); `bootstrapSession` só loga falha. Padrão de query/mutation: `useReview.query.ts` / `useDismissReview.mutation.ts` (zod na queryFn, toast on success).
- Env: zod `envSchema` em `config/env.validation.ts`; `.env.example` raiz documenta `REFRESH_TOKEN_TTL_DAYS`.
- Migrações: SQL manual em `apps/api/prisma/migrations/<ts>_<nome>/migration.sql`; precedente `20261011150000_multi_day_conflict_endsAt_index`.
- Jest api: `testRegex .*\.service\.spec\.ts$` (mocks de prisma em memória); zod dos contracts testado com vitest em `packages/contracts/src/api/*.spec.ts`.
- Cookies: express sem `cookie-parser`?? — SIM (`main.ts` usa; controller já lê `req.cookies`).

## 3. Decisões

| #   | Decisão                                                                                                                                         | Alternativa descartada              | Por quê                                                                                                                                                            |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | `computeSessionExpiry` pura em `session-expiry.ts` com `now/loginAt/ttls` por parâmetro + service com `now` injetável (`protected now(): Date`) | Date.now() solto no service         | Regra de data → TDD obrigatório + gotcha do repo (tempo controlável)                                                                                               |
| D2  | `GET /auth/sessions` (REST de leitura) em vez de `POST /auth/sessions` literal do brief                                                         | POST para listar                    | Verbo "POST" lido como typo de rota; GET é o REST do repo (`GET /review`) e o teste web asssume listagem; decisão registrada aqui para o humano reverter se quiser |
| D3  | Logout resolvido pelo hash do cookie de refresh (endpoint continua público), sem Bearer                                                         | exigir access token                 | access pode estar expirado (15min) na hora do "Sair"; o pedido é "resolve pelo refresh; nunca 401"                                                                 |
| D4  | Fingerprint = user-agent (ip registrado mas não comparado)                                                                                      | ip+ua estritos                      | ip flutua (rede móvel/CGNAT) → e-mail de alarme falso; spec do humano: "nenhuma sessão ativa com o mesmo user-agent"                                               |
| D5  | `current` definido pela linha cujo tokenHash bate com o cookie; sem match → lista sem `current` e DELETE revoga tudo                            | 400/401 quando cookie inválido      | logout/listagem nunca falham por cookie; sessão "atual" pode ter morrido no teto                                                                                   |
| D6  | maxAge do refresh = `expiresAt - now` real                                                                                                      | TTL fixo                            | exigência humana nº 1                                                                                                                                              |
| D7  | `forceLogout` no authStore (usa `router` importado direto, como main.ts) + toast no chamador                                                    | composable useAuthExpiry com inject | store já é o dono do estado; inject de router fora de setup é dor; import direto do singleton do router é o padrão do bootstrap                                    |
